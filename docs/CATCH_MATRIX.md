# Catch matrix

Every planted bug, switched on **by itself**, and the tests that failed because of it.
Generated by `npm run catch-matrix`. A bug with no failing test would fail the build.

Baseline with no bugs on: **81 unit** and **35 E2E** (Chromium) tests, all passing.

**Result: 10 of 10 bugs caught.**

| # | Bug | Kind | Unit tests that fail | E2E tests that fail |
|---|---|---|---|---|
| 1 | Free delivery misses ₱500 exactly | Boundary value | `totals delivery is free at exactly ₱500 after discounts (4 Classic + Matcha with pearls = ₱550, WELCOME50)` | `Promo codes and delivery › delivery is free at exactly ₱500 @smoke` |
| 2 | A 4th topping sneaks in | Off-by-one | `toppings allows exactly 3 toppings and refuses a 4th` | `Building and ordering drinks › up to 3 toppings: a 4th is refused with a message` |
| 3 | Promo codes are case-sensitive | Input handling | `promo codes accepts "boba10" regardless of case and spaces`<br>`promo codes accepts "  Boba10 " regardless of case and spaces`<br>`promo codes accepts "welcome50" regardless of case and spaces`<br>`promo codes applying the same code again keeps a single promo` | `Promo codes and delivery › promo codes work however they are typed` |
| 4 | The same promo applies twice | State | `promo codes applying the same code again keeps a single promo` | `Promo codes and delivery › applying the same code twice does not double the discount` |
| 5 | Large size overcharges toppings | Calculation | `unit price a Large surcharge applies once to the drink, never per topping`<br>`totals: invariants for any order a Large always costs exactly ₱20 more than the same drink in Regular` | `Building and ordering drinks › build a drink, add it, see it in the order @smoke`<br>`Building and ordering drinks › Large costs ₱20 more for the drink, not per topping` |
| 6 | Remove deletes the wrong drink | State | `cart removes exactly the line asked for, even when the same drink is in the cart twice` | `Building and ordering drinks › removing one of two Taro drinks removes the one you clicked` |

| 8 | Your order vanishes on refresh | Persistence | `saved order what is saved is exactly what loads back`<br>`saved order survives corrupted or tampered data` | `Saved order › the order, promo and delivery choice survive a reload @smoke`<br>`Saved order › corrupted saved data starts a fresh order instead of crashing` |
| 9 | Buy 1 Take 1 frees the pricier drink | Business rule | `Buy 1 Take 1 Tuesdays makes the CHEAPER drink of a pair free`<br>`Buy 1 Take 1 Tuesdays frees one drink per pair: 3 drinks → 1 free, 4 → 2 free (the two cheapest)`<br>`totals applies Buy 1 Take 1 before the promo code`<br>`totals: invariants for any order Buy 1 Take 1 never frees more than half the drinks, and never the priciest of a pair` | `Buy 1 Take 1 Tuesdays › on a Tuesday › the cheaper drink of a pair is free @smoke` |
| 10 | Keyboard users can’t add to order | Accessibility | – | `Accessibility › a keyboard-only customer can build and add a drink @smoke` |

## Why two layers

Nine bugs are caught by fast unit tests on the pricing rules. The keyboard bug lives only in the UI,
so only a browser test (Tab to the button, press Enter) can catch it. The persistence bug is caught by
both: a unit test with an in-memory storage, and an E2E test that really reloads the page.
